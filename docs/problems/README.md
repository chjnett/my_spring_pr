# 문제 백로그

여기는 아직 해결하지 않은 문제를 모으는 곳이다. N+1, 캐시, 락처럼 기술 이름을 먼저 고르지 않는다. SecureFlow에서 실제로 어떤 잘못된 상태가 생길 수 있는지부터 정의한다.

문제 하나는 다음 상태를 거친다.

```text
문제 후보 → 재현 설계 → 딥다이브 → PAAR 사례 연구 → 기술 블로그 후보
```

## 문제 후보를 채택하는 기준

1. 사용자·데이터·운영 중 무엇이 잘못되는지 한 문장으로 말할 수 있다.
2. 테스트나 로그로 실패를 재현할 수 있다.
3. 해결책이 둘 이상이라 선택 근거를 비교할 수 있다.
4. 결과를 최소 하나의 수치로 확인할 수 있다.

기술 키워드만 있는 "N+1 공부하기"는 문제 후보가 아니다. "관리자 목록을 조회할 때 사용자 100명을 함께 읽으면 쿼리가 101번 발생한다"처럼 관찰 가능한 실패 상태여야 한다.
